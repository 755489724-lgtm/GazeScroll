v5.44 A/B 对照：同一套离线回放，跑在两版常量上
================================================

回放脚本：tools\headpose-replay\run.ps1（编译**真实的** HeadPoseDetector.kt，只把 android.util.Log
换成打印桩）。动作形状抄的是 2026-09-17 19:16:23 那次实测：**慢起手（onset 爬到阈值附近）→ 一帧快越阈值
（speed≈0.057°/ms）→ 保持**。起手时长用那一场实测到的 6 个值：336 / 429 / 429 / 563 / 684 / 839 ms。

------------------------------------------------------------
A) 旧常量 NEAR_SUDDEN_RISE_MS = 300L（v5.28 起，用户报"仰头失灵"的那一版）
------------------------------------------------------------
  PASS  起手 336ms → 应触发
  FAIL  起手 429ms → 应触发        实际触发 0 次     ←←← 就是用户 19:16 那次
  FAIL  起手 429ms → 应触发        实际触发 0 次
  PASS  起手 563ms → 仍然应被挡（慢晃）
  PASS  起手 684ms → 仍然应被挡（慢晃）
  PASS  起手 839ms → 仍然应被挡（慢晃）
  PASS  远档起手 400ms → 触发
  PASS  远档起手 700ms → 被挡（>500ms）
  PASS  近档点头 200ms → 触发（A 方案没做，阈值仍是 2.5°）
  PASS  近档边缘 + 匀速慢晃 700ms → 不触发
=== 结果：2 项失败 ===

------------------------------------------------------------
B) 新常量 NEAR_SUDDEN_RISE_MS = 450L（v5.44）
------------------------------------------------------------
  PASS  起手 336ms → 应触发
  PASS  起手 429ms → 应触发        ←←← 修好了
  PASS  起手 429ms → 应触发
  PASS  起手 563ms → 仍然应被挡（慢晃）
  PASS  起手 684ms → 仍然应被挡（慢晃）
  PASS  起手 839ms → 仍然应被挡（慢晃）
  PASS  远档起手 400ms → 触发
  PASS  远档起手 700ms → 被挡（>500ms）
  PASS  近档点头 200ms → 触发（A 方案没做，阈值仍是 2.5°）
  PASS  近档边缘 + 匀速慢晃 700ms → 不触发
=== 结果：全部通过 ===

结论
----
* 429ms 的仰头：旧版整段作废（0 次触发），新版能触发 —— 修的就是用户报的那件事。
* 563ms 以上的慢晃：两版都被挡 —— 窗口没有被放宽到失去意义。
* 远距离（窗口仍用用户设的 500ms）与近档点头（阈值仍 2.5°）行为**完全没变**。

复现 A 的做法：把 HeadPoseDetector.kt 复制一份，只把 `NEAR_SUDDEN_RISE_MS = 450L` 改回 300L，
再用 run.ps1 里的同一条 kotlinc 命令编译即可（回放脚本与常量无关）。
